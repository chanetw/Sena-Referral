API Reference

POST /api/auth/register

เอกสารสำหรับทีมภายนอกที่ต้องการเชื่อมระบบสมัคร Agent แบบ server-to-server

สรุปให้อ่านง่าย ใช้งานจริงได้ทันที โดยเน้นเฉพาะ endpoint นี้

MethodPOST
Path/api/auth/register
AuthX-Api-Key required
Bodyapplication/json

1) ใช้อย่างไรแบบสั้นที่สุด

  1. ยิง POST ไปที่ /api/auth/register
  2. ใส่ header X-Api-Key และ Content-Type: application/json
  3. ส่งข้อมูลหลักให้ครบ: firstName, lastName, email, idCard
เหมาะกับ: ระบบภายนอกที่เชื่อมเข้ามาแบบ backend-to-backend
ไม่เหมาะกับ: public form ทั่วไป (กรณีนั้นให้ใช้ POST /api/auth/register-agent)

2) Request URL

POST http://<HOST>:4000/api/auth/register

3) Required Headers

Header Required Example คำอธิบาย
Content-Type Yes application/json ระบุว่าข้อมูลที่ส่งเป็น JSON
X-Api-Key Yes <YOUR_REGISTER_API_KEY> ใช้ยืนยันสิทธิ์ก่อนเรียก API

4) Request Body

Field Type Required คำอธิบาย
firstNamestringYesชื่อ
lastNamestringYesนามสกุล
emailstringYesอีเมลสำหรับใช้งานในระบบ
idCardstringYesเลขบัตรประชาชน 13 หลัก
phonestringNoเบอร์โทรศัพท์
agentTypeCodestringRecommendedค่าที่รองรับจากตาราง agent_types: resident, livnex_customer, rentnex_customer, sena_staff, partner, general
projectIdnumberNoรหัสโครงการจากระบบหลัก
projectTextstringNoชื่อโครงการแบบข้อความ
referralCodestringNoรหัสอ้างอิง
houseNumberstringNoบ้านเลขที่
departmentstringNoแผนก
divisionstringNoฝ่าย
companyNamestringNoชื่อบริษัท
occupationstringNoอาชีพ
knowSenaFromstringNoช่องทางที่รู้จัก SENA
หมายเหตุ: ถ้าส่ง projectId มา ระบบจะ lookup ชื่อโครงการและบันทึกลง projectText ให้อัตโนมัติ

ค่าที่รองรับสำหรับ agentTypeCode

ID Code ชื่อที่ใช้แสดงผล
1residentลูกบ้าน
2livnex_customerลูกค้า LIvnex
3rentnex_customerลูกค้า Rentnex
4sena_staffพนักงานบริษัทเสนาฯ และบริษัทในเครือ
5partnerพันธมิตร คู่ค้า
6generalบุคคลทั่วไป

อ้างอิงค่าจริงจากตาราง agent_types ใน `init-database.sql` และ `database-schema.sql`

7) Error Responses

Status กรณี ความหมาย
400 ข้อมูลไม่ครบ / format ไม่ถูกต้อง เช่น email ไม่ถูกต้อง หรือ idCard ไม่ครบ 13 หลัก
401 Api Key ไม่ถูกต้อง ไม่ได้ส่ง X-Api-Key หรือ key ผิด
409 ข้อมูลซ้ำ อีเมลหรือเลขบัตรประชาชนมีอยู่ในระบบแล้ว

ตัวอย่าง: ID Card ซ้ำ

{
  "success": false,
  "message": "เลขประจำตัวประชาชนนี้ถูกใช้แล้ว",
  "errorType": "idCard",
  "existingData": {
    "agentCode": "AG012",
    "firstName": "สมชาย",
    "lastName": "ใจดี",
    "email": "old@example.com"
  },
  "nextAction": "contact_admin"
}

ตัวอย่าง: Email ซ้ำ

{
  "success": false,
  "message": "อีเมลนี้ถูกใช้แล้ว",
  "errorType": "email"
}

8) กติกาสำคัญ

  • Backend เป็นผู้สร้าง agentCode, refCode และข้อมูลระบบอื่นให้อัตโนมัติ
  • ผู้เรียก API ไม่ต้อง map agentTypeCode เป็น id เอง
  • ถ้าไม่ต้องการผูกกับ master project สามารถส่งเฉพาะ projectText ได้
